## Reuse safely / Réutiliser sans problème

1. Check the upstream **LICENSE**. Public visibility and the ability to fork do not automatically grant permission to copy or distribute code.
2. Read the upstream README and its installation requirements. Check latest releases and unresolved security issues.
3. Prefer a **template repository** for a fresh project, a **fork** when you intend to contribute changes upstream, or a library dependency when you only need a feature.
4. Preserve attribution and license files where required. Do not copy secrets, production credentials or customer data.
5. Run tests and security checks before deployment; pin and update dependencies deliberately.
6. Record the upstream URL, version or commit, license and changes you made.

## Decision guide / Quel choix ?

- **Need a new independent project?** Use a permitted template or starter kit. / Nouveau projet : partir d'un modèle.
- **Need to help improve an existing project?** Fork -> branch -> tests -> Pull Request. / Contribution : fork et PR.
- **Need a single feature?** Install a maintained library instead of copying its entire source. / Fonction isolée : bibliothèque adaptée.
- **Need to learn?** Bookmark and study source and documentation. / Apprentissage : conserver les liens.

## Personal checklist for every new project

- [ ] Clear problem and users
- [ ] Choose language/framework and a valid license
- [ ] Repository README with installation instructions
- [ ] Minimal working example and tests
- [ ] GitHub Actions CI
- [ ] .gitignore, sample environment file (never real secrets)
- [ ] Screenshots or verified demo (if UI)
- [ ] Security check and suitable release documentation
